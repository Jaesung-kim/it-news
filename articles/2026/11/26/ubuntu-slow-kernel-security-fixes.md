# 우분투 커널 보안 패치 지연 논란…원격 TCP 취약점 'NoisyTCP'·AMD KVM 탈출 취약점 아직 미수정

- 분야: IT 뉴스
- 출처: oss-security 메일링 리스트, GeekNews, Hacker News
- 원문: https://www.openwall.com/lists/oss-security/2026/11/25/9
- 발행일: 2026-11-25
- 공식 출처: https://ubuntu.com/security/CVE-2026-99288 , https://ubuntu.com/security/CVE-2026-99312 , https://ubuntu.com/security/CVE-2026-98432

## 상세 요약

보안 연구자 하노 뵈크(Hanno Böck)가 11월 25일 오픈소스 보안 메일링 리스트 oss-security에 '느린 우분투 보안 대응'이라는 글을 올렸다. 그는 심각한 커널 취약점에 대한 우분투의 대응 속도가 우려스럽다며, 원격 메모리 손상 같은 커널 결함은 며칠이나 몇 주가 아니라 몇 시간 안에 수정본이 나와야 한다고 주장했다.

첫 사례는 리눅스 TCP 스택의 원격 메모리 손상 취약점 'NoisyTCP'(CVE-2026-99288)다. 뵈크는 세부 내용이 공개된 지 9일이 지나도록 우분투 수정본이 없다고 지적했다. 다른 배포판은 공개 시점에 이미 수정본을 내놨다고 했지만, 어느 배포판인지는 밝히지 않았다.

두 번째는 AMD 가상화 환경에 영향을 주는 KVM 호스트 탈출 취약점 CVE-2026-99312다. 11월 18일 공개됐지만 글을 쓴 시점까지 수정본이 없었다. 세 번째로 그는 원격 TCP 메모리 손상 취약점 CVE-2026-98432의 수정에 우분투가 몇 주가 걸렸다고 짚었다. 이 취약점은 실제 공격에 악용되고 있을 가능성도 있다고 했다.

우분투 공식 CVE 추적 페이지도 이 상황을 보여준다. CVE-2026-99288은 우선순위 '높음', CVSS 3 점수 5.9이며 26.04, 24.04, 22.04 등에서 '취약, 작업 중' 상태다. CVE-2026-99312는 우선순위 '높음', CVSS 3 점수 8.8이고 26.04, 24.04, 22.04가 '취약' 상태로 표시돼 있다. CVE-2026-98432는 우선순위 '긴급', CVSS 3 점수 9.8로, 현재는 지원 중인 버전 대부분에서 수정이 끝났다.

뵈크는 원인으로 커널 관리 방식을 꼽았다. 우분투는 자체 커널(7.0.0-44 등)에 수정 사항을 골라 옮기는 백포트 방식을 쓰는 반면, 데비안은 kernel.org의 장기 지원(LTS) 커널을 기반으로 한다는 것이다. 그는 배포판들이 kernel.org 장기 지원 커널을 기반으로 삼아야 한다고 주장했다.

메일링 리스트 게시물 기준으로 캐노니컬(Canonical)의 공식 답변은 아직 없다. 우분투는 서버와 클라우드에서 널리 쓰이는 배포판이어서 원격 커널 취약점의 수정 지연은 운영자에게 직접적인 부담이 된다. CVE-2026-98432 페이지에는 헤더 옵션이 붙은 IPv4 TCP 패킷을 방화벽에서 차단하는 완화책이 안내돼 있다.

## 핵심 포인트

- 하노 뵈크가 oss-security에서 우분투의 커널 보안 패치 지연을 비판했다
- 원격 TCP 취약점 NoisyTCP(CVE-2026-99288)는 공개 9일 뒤에도 우분투 수정본이 없었다
- AMD KVM 호스트 탈출 취약점 CVE-2026-99312(CVSS 8.8)도 미수정 상태다
- CVSS 9.8의 CVE-2026-98432는 수정까지 몇 주가 걸렸다
- 뵈크는 백포트 대신 kernel.org 장기 지원 커널을 기반으로 삼아야 한다고 주장했다
