# 엘릭서·얼랭 패키지 저장소 Hex.pm 침해…비인증 요청으로 웹 서버 6대서 명령 실행, 이용자에 비밀번호·2FA 재설정 권고

## 상세 요약

엘릭서(Elixir)와 얼랭(Erlang) 생태계의 공식 패키지 저장소 Hex.pm이 11월 24일 공식 블로그에 보안 사고 보고서를 올렸다. 11월 23일(UTC) 외부 공격자가 비인증 요청 처리 취약점을 이용해 웹 서버에서 운영체제 명령을 실행했다. 보고서는 피터 울리히, 요나탄 맨헨, 에릭 메도스-욘손이 작성했다.

공격자는 18시 16분부터 18시 29분까지 악성 요청 69건을 보냈다. Hex 팀은 18시 27분 방화벽 규칙을 추가해 18시 33분까지 차단을 마쳤고, 18시 30~31분 모든 서버를 수정된 빌드로 교체했다. 공격이 시작된 지 20분 안에 차단과 수정 배포가 끝난 셈이다. 같은 취약점을 알리는 보안 제보는 19시 7분에 따로 들어왔다. 익스플로잇이 실행된 웹 서버는 6대였고, 그중 3대는 18시 28분 취약한 빌드로 새로 띄운 서버였다.

취약점은 `application/vnd.hex+erlang` 형식의 비인증 요청 본문을 해석하는 과정에 있었다. 안전 모드 디코딩이 맵을 검사하지 않아, `__struct__` 키를 넣은 위조 엘릭서 구조체가 그대로 통과했다. 이 값이 오류를 일으키면 오류 로그를 남기는 `inspect` 과정이 `Ecto.Query.DynamicExpr`와 `DBConnection.Stream`으로 이어졌고, `:log` 옵션에 담긴 공격자의 모듈·함수·인자 조합이 실행됐다. 보고서에 따르면 이를 막던 안전 검사는 2016년 2월 23일 코드에서 빠졌다.

Hex 팀은 데이터베이스 비교, 패키지 파일 62개와 레지스트리 파일 186개의 체크섬 검사, 클라우드 감사 로그 확인을 거쳐 패키지 변조나 데이터베이스 변경, 지속적인 접근 흔적은 없다고 밝혔다. 그러나 데이터베이스 읽기, 환경 변수 읽기, 클라우드 스토리지 직접 읽기는 로그가 남지 않는다. 이메일, 비밀번호 해시, API 키 해시, 2FA 비밀값, 세션, 감사 로그가 열람됐을 가능성은 배제할 수 없다는 뜻이다.

후속 조치로 자격 증명을 교체했고 24일 오전까지 마무리했다. 스웨덴 개인정보 감독기관(IMY), 미국 CISA, 유럽 ENISA에 침해 사실을 신고했다. 24일 CVE-2026-129514를 발행했다. CVE 기록에는 얼랭 생태계 재단(EEF)이 발급 기관으로, CVSS v4.0 점수 10.0(긴급)과 실제 공격 사실이 올라 있다. 팀은 관련 라이브러리 db_connection의 `:log` 콜백 문제(CVE-2026-133555)와 Ash 페이지네이션 문제(CVE-2026-124283, ash 3.38.0에서 수정)도 함께 추적하고 있다. 수정 커밋은 `__struct__` 맵이 포함된 요청을 HTTP 400으로 거부하며, plug_crypto, plug, ecto, db_connection 보강도 진행 중이다.

이용자에게는 hex.pm 비밀번호 변경과 2FA 재설정을 권고했다. 새 서명 체계가 나오면 `mix local.hex --force`를 실행하고 rebar3나 Gleam도 업데이트하라고 안내했다. 그때까지는 "don't trust third-party mirrors and fetch packages only from repo.hex.pm"이라고 당부했다. API 키는 무작위 128비트 값을 HMAC-SHA256으로 저장하기 때문에 교체가 필요 없다고 설명했다. Hex를 사칭한 피싱 메일에 대한 주의도 덧붙였다.

## 핵심 포인트

- 11월 23일 비인증 요청 69건으로 Hex.pm 웹 서버 6대에서 OS 명령이 실행됐다
- 위조 엘릭서 구조체가 오류 로깅 경로를 거쳐 공격자 코드를 실행시키는 연쇄 취약점이었다
- 공격 20분 안에 차단과 수정 배포를 마쳤고 패키지 변조 흔적은 없었다
- 데이터베이스 읽기 로그가 없어 이메일·해시·2FA 비밀값 노출 가능성은 남는다
- CVE-2026-129514가 발행됐고, 이용자에게 비밀번호와 2FA 재설정을 권고했다
