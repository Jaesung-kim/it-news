# 웹 프레임워크 Solid 2.0 정식 출시…비동기 반응성·서버 함수 내장, SolidStart는 은퇴

- 분야: IT 뉴스
- 출처: Solid 공식 블로그 (Hacker News 소개)
- 원문: https://www.solidjs.com/blog/solid-2-0-the-long-hold
- 발행일: 2026-11-16

## 상세 요약

자바스크립트 UI 프레임워크 Solid가 2.0 정식 버전을 내놓았다. 개발자 라이언 카르니아토는 공식 블로그 글 'The Long Hold'에서 1.0 이후 약 5년 만의 메이저 업데이트라며, 반응성 그래프 안의 비동기 처리, 서버 함수, 에이전트를 위한 진단 기능, 더 작아진 API를 핵심 변화로 꼽았다.

가장 큰 변화는 비동기 처리다. 계산 함수가 프라미스나 비동기 이터레이터를 돌려주면 이를 이어받는 코드가 알아서 처리한다. 예를 들어 `createMemo`로 사용자 정보를 불러오고 `<Loading>` 경계로 대기 화면을 보여주며, `isPending`으로 이전 값이 표시되는 상태를 확인할 수 있다. 낙관적으로 미리 반영한 상태는 자동으로 되돌려져 서버가 기준 데이터 역할을 유지한다고 설명했다.

서버 함수는 프레임워크 핵심에 들어왔다. `"use server"` 비동기 제너레이터로 서버 전송 이벤트(SSE)를 통해 데이터를 실시간으로 흘려보내는 예시도 소개됐다. 반응형 서버 컴포넌트는 몇 주 안에 따로 발표할 예정이다. 그동안의 메타프레임워크였던 SolidStart는 은퇴시키고, 그 기능을 핵심 라이브러리와 프레임워크에 묶이지 않는 Vite 플러그인으로 나눴다.

개발 빌드에는 반응성 실수를 잡아내는 진단 기능이 들어갔다. 효과 콜백에서 반응형 값을 추적 없이 읽는 경우 등을 고정된 오류 코드, 소스 위치, 수정 안내 링크와 함께 알려주고, 요청 폭포(워터폴)나 효과 무한 루프도 찾아낸다. 이 정보는 크롬 성능 도구와 센트리 플러그인에도 연결된다. 블로그는 이를 사람뿐 아니라 코딩 에이전트도 읽고 고칠 수 있게 만든 설계라고 소개했다.

API는 줄었다. `createResource`, `batch`, `startTransition`, `on`, `produce`, `createComputed`, `createMutable`이 모두 빠졌고, 상태를 저장하기보다 파생시키는 방식을 권장한다. 별도 마이그레이션 가이드는 글에 없으며 v2 문서를 안내했다. 실험 기능으로 ReactiveScript와 TSRX 문법 지원도 추가됐다.

개발 과정도 공개됐다. 2.0 작업은 2024년 말 본격 시작돼 2025년 2월 로드맵이 발표됐고, 반응성 핵심을 다시 쓴 뒤 3월 베타, 8월 릴리스 후보(RC)가 나왔다. 14주 동안 RC 23개를 내며 PR 971개를 병합하고 이슈 753개를 닫았다. 일반 앱 코드에서 회귀 없이 일주일을 버티는 것을 정식 출시 기준으로 삼았다. 성능 수치는 따로 제시하지 않았고 "철저한 점검이 아니라 구조 자체로 안전하게"라는 방향을 강조했다.

## 핵심 포인트

- Solid가 약 5년 만의 메이저 버전 2.0을 정식 출시했다
- 반응성 그래프가 프라미스·비동기 이터레이터를 직접 처리하고 서버 함수가 핵심에 들어왔다
- 메타프레임워크 SolidStart를 은퇴시키고 Vite 플러그인 체계로 바꿨다
- createResource·batch 등 여러 API를 없애고 에이전트도 읽을 수 있는 진단 기능을 넣었다
- RC 23개, PR 971개 병합, 이슈 753개 처리를 거쳐 안정판이 됐다
