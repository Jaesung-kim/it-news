# curl 개발자 스텐베리, AI가 만든 curl의 러스트 재작성판들에 "쓰는 것보다 유지가 어렵다"

- 발행일: 2026-11-17

## 상세 요약

네트워크 전송 도구 curl을 만든 다니엘 스텐베리가 17일 개인 블로그에서 최근 잇따라 등장한 curl의 러스트(Rust) 재작성 프로젝트들을 다뤘다. 올가을에만 두 개가 나왔다. 몇 달 전 공개된 'urlx'는 메모리 안전한 처음부터의 재구현을 내세웠고, 11월에 나온 'curl, rewritten in Rust'는 이름까지 curl을 그대로 썼다. 두 번째 프로젝트는 비용으로 8600달러를 들였다고 밝혔다.

스텐베리는 코드를 한 번 작성하는 일이 어려운 부분이 아니라고 지적했다. AI 에이전트가 curl을 변환할 수 있었던 것도 curl에 방대한 문서, 이를 쓰는 수많은 애플리케이션, 수천 개의 테스트가 이미 갖춰져 있었기 때문이라는 설명이다.

규모도 소개됐다. 에이전트들은 3주 남짓 동안 약 18만5000줄의 C 코드를 약 34만 줄의 러스트 코드로 바꿨다. 그런데 같은 기간 원본 curl에는 300개가 넘는 커밋이 병합됐고, 그중 200개 남짓은 버그 수정이었으며 취약점 수정도 일부 포함됐다. 재작성 프로젝트들은 이 수정을 하나도 반영하지 못한 상태다.

메모리 안전성 논쟁에 대한 수치도 제시했다. 2026년 확인된 curl 취약점 81개 가운데 14개(17.3%)가 메모리 안전한 언어를 썼다면 피할 수 있었을 C 언어 실수였다. 스텐베리는 "14개는 러스트 같은 메모리 안전 언어를 썼다면 대부분 피할 수 있었던 실수의 결과"라고 썼다. 거꾸로 보면 나머지 67개는 러스트 버전에도 그대로 있었을 것이라는 뜻이다.

스텐베리는 자신이 재작성을 믿지 않으며 지속적인 다듬기와 리팩터링을 선호한다고 밝혔다. 재작성 프로젝트 측과 연락한 적은 없으며, 이 상황이 재미있고 당혹스러우면서도 흥미롭다고 했다. 그러면서도 두 프로젝트에 행운을 빈다고 덧붙였다.

## 핵심 포인트

- 올가을 curl의 러스트 재작성 프로젝트 urlx와 'curl, rewritten in Rust'가 등장했다
- AI 에이전트가 3주 남짓 만에 C 코드 약 18만5000줄을 러스트 약 34만 줄로 바꿨다
- 같은 기간 원본 curl의 300개 넘는 커밋과 200여 개 버그 수정은 반영되지 않았다
- 2026년 curl 취약점 81개 중 메모리 안전 언어로 막을 수 있었던 것은 14개였다
- 스텐베리는 재작성보다 지속적인 개선이 낫다는 입장을 밝혔다
