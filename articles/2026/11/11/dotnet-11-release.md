# 마이크로소프트, .NET 11 정식 출시…C# 15 유니언 타입 도입, 구형 CPU 지원 중단

## 상세 요약

마이크로소프트가 11월 10일 .NET 11을 정식 출시했다. 지원 기간 2년인 표준 지원(STS) 버전이며, 장기 지원(LTS)이 필요한 곳은 계속 .NET 10을 쓰면 된다. 같은 날 .NET 8과 .NET 9의 지원이 끝났고, 온라인 행사 .NET Conf는 13일까지 열린다.

언어 쪽에서는 C# 15가 기본 버전이 되면서 유니언 타입과 닫힌 계층 구조가 들어왔다. SDK는 네이티브 AOT로 만든 CLI 호스트와 상시 대기하는 MSBuild 서버를 기본으로 켜 빌드 속도를 높였고, NuGet에는 공개된 지 일정 기간이 지난 패키지만 받도록 하는 설정이 생겼다. 웹 쪽은 OpenAPI 3.2가 기본이 됐고, .NET MAUI는 CoreCLR을 기본 런타임으로 삼는다. 라이브러리에는 Zstandard 압축과 LINQ FullJoin 등이 추가됐으며, `dotnet new mcpserver` 템플릿도 포함됐다.

런타임에서 가장 큰 변화는 최소 하드웨어 요구사항이다. x86/x64는 x86-64-v2 명령어 세트가 필수가 됐고, 윈도 Arm64는 LSE 확장을 요구한다. 이를 갖추지 못한 구형 CPU에서는 시작 단계에서 오류가 나며 실행되지 않는다. ReadyToRun 이미지는 x86-64-v3를 목표로 컴파일된다.

미리보기로 들어온 '런타임 비동기(Runtime Async)'는 컴파일러가 만들던 상태 머신 대신 런타임이 비동기 실행의 중단과 재개를 관리한다. 문서 예시에서 실행 중 스택 추적이 13프레임에서 5프레임으로 줄어 디버깅이 쉬워진다.

성능 개선도 이어졌다. JIT는 불필요한 경계 검사와 가상 호출을 더 많이 없애고, 지원 CPU에서는 Half 연산에 하드웨어 FP16 명령을 쓴다. ReadyToRun 이미지에서 기본 비교자를 특수화해 관련 컬렉션 작업이 최대 20배 빨라졌고, JIT가 없는 플랫폼의 인터페이스 호출은 최대 200배 개선됐다. 논리 CPU 1024개 초과 지원과 리눅스·macOS 프로세스 내 크래시 리포트도 추가됐다.

마이크로소프트는 .NET에 7000명 넘는 기여자가 참여하고 있으며 NuGet 패키지가 58만 9000개를 넘었다고 밝혔다.

## 핵심 포인트

- .NET 11은 2년 지원 STS 버전이며 같은 날 .NET 8·9 지원이 종료됐다
- C# 15 유니언 타입, OpenAPI 3.2 기본, MAUI의 CoreCLR 기본 채택 등이 포함됐다
- x86-64-v2(윈도 Arm64는 LSE) 미지원 구형 CPU에서는 실행되지 않는다
- 런타임 비동기 미리보기로 스택 추적과 디버깅이 개선된다
- 기본 비교자 최대 20배, 비JIT 플랫폼 인터페이스 호출 최대 200배 성능 개선
