## 상세 요약

루비 개발팀이 정규 표현식(Regexp) 엔진과 문자열 대소문자 변환 기능에서 발견된 취약점 7건을 공식 보안 공지로 공개했다. 공지는 11월 18일(UTC 기준 19일 0시) 게시됐다. 일부 취약점은 특정 조건에서 원격 코드 실행(RCE)까지 이어질 수 있다. 개발팀은 이를 입증하는 개념 증명(PoC) 코드가 있다는 사실도 알고 있다고 밝혔다.

취약점은 두 갈래다. 하나는 조작된 문자열의 대소문자를 바꿀 때 생기는 문제다. ISO-8859-1·Windows-1252 같은 1바이트 인코딩에서 1바이트 힙 버퍼 오버플로가 생기고, 정수 오버플로가 힙 버퍼 오버플로로 번지는 경우도 있다. 다른 하나는 공격자가 정한 정규식 패턴을 컴파일하거나 매칭할 때 생기는 문제다. 정규식 컴파일 과정의 이중 해제(double free)와 정수 오버플로, 대소문자 무시 매칭의 범위 밖 읽기, `Regexp#to_s`의 힙 버퍼 오버플로가 포함됐다.

위험도는 취약점마다 다르다. 5건은 원격 코드 실행 가능성이 언급됐고, 1건은 정보 유출이나 원격 코드 실행으로 이어질 수 있다. 대소문자 무시 역참조 매칭의 범위 밖 읽기 1건은 메모리 내용 노출이나 프로세스 충돌 수준으로 분류됐다. 문자열 대소문자 변환의 1바이트 오버플로는 깃허브 보안 권고(GHSA)에서 '치명적(Critical)' 등급을 받았다.

발견자는 여럿이다. 4건은 Ada Logics의 스테판 립(Stephan Lipp)과 앤트로픽이 함께 찾았고, 2건은 해커원(HackerOne) 제보자가 보고했다. 나머지 1건은 루비 커미터들이 찾았다. 7건 모두 GHSA 번호만 있고 CVE 번호는 아직 없다. 공지에는 CVE 번호를 요청했지만 아직 배정되지 않았다고 적혀 있다.

영향을 받는 버전은 루비 3.3.13 이하, 3.4.0~3.4.12, 4.0.0~4.0.9다. 수정 버전은 4.0.10, 3.4.13, 3.3.14이며 개발팀은 이 버전으로 올리라고 강하게 권고했다. 3.3 계열은 보안 유지보수 단계라 이번 수정을 받지만, 3.2 이하는 지원이 끝나 패치가 나오지 않는다.

정규식 패턴이나 변환 대상 문자열을 외부 입력으로 받는 웹 애플리케이션이 특히 위험하다. 루비는 10월에도 깃랩(GitLab) 관련 CVE 4건에 대응해 정규식 컴파일 수정을 내놓은 바 있다. 정규식 엔진 쪽 보안 수정이 두 달 연속 나온 셈이다.

## 핵심 포인트

- 루비 정규식 엔진과 문자열 대소문자 변환에서 메모리 손상 취약점 7건이 공개됐다
- 힙 버퍼 오버플로, 이중 해제, 범위 밖 읽기가 포함되며 일부는 RCE PoC가 존재한다
- 수정 버전은 4.0.10·3.4.13·3.3.14이고, 지원이 끝난 3.2 이하는 패치가 없다
- 7건 모두 GHSA로 공개됐고 CVE 번호는 요청 중이다
- 4건은 Ada Logics 연구자와 앤트로픽이 함께 발견했다
