## 상세 요약

리플릿이 사용자와 자율 에이전트가 코드를 실행하는 샌드박스 엔진을 처음부터 다시 만들었다고 공식 엔지니어링 블로그에서 밝혔다. 회사는 지난 몇 달 동안 새 엔진을 전면 배포했고, 이 과정에서 수억 개 프로젝트를 데이터 손실이나 보고된 서비스 중단 없이 옮겼다고 설명했다. 작업은 2025년 11월에 시작해 2026년 2월부터 사내에서 쓰였고, 이후 몇 달째 프로덕션에서 안정적으로 돌아가고 있다고 한다.

가장 큰 변화는 격리 방식이다. 기존 엔진은 구글 컴퓨트 엔진 VM 위에서 도커로 코드를 실행해 샌드박스들이 호스트의 리눅스 커널을 함께 썼다. 새 엔진은 샌드박스마다 자체 리눅스 커널을 가진 microVM을 띄운다. KVM으로 각 샌드박스를 격리하고, 가상머신 관리자로는 파이어크래커 대신 클라우드 하이퍼바이저를 골라 스냅숏 이식성을 위한 패치를 더했다. VM 안에서는 다시 역할별 컨테이너로 프로세스를 나누고 네임스페이스, seccomp, 권한(capabilities)으로 범위를 좁힌다.

보안 설계에도 공을 들였다. 게스트 커널은 최소 구성인 tinyconfig에서 출발해 필요 없는 하드웨어 드라이버를 빼고 모듈 로딩을 막았다. 리플릿은 2026년 6월 1일부터 11월 4일까지 공개된 리눅스 커널 CVE 6211건을 점검한 결과 5969건(96.1%)을 피했다고 밝혔다. 이 가운데 4375건은 업스트림 수정을 먼저 반영했고, 676건은 설정에서 해당 코드를 빼서 피했다는 설명이다. 회사는 원격 루트 탈취로 이어질 수 있는 리눅스 TCP 결함(CVE-2026-98432)도 CVE 공개 전인 10월 12일에 이미 수정해 두었다고 적었다.

실행 중 감시와 통제는 eBPF와 리눅스 보안 모듈(LSM)이 맡는다. eBPF로 프로세스·파일·네트워크 활동을 관찰하고 LSM으로 금지된 동작을 막는다. 샌드박스마다 붙는 보안 모니터는 변경이 병합된 뒤 15분 안에 전체 프로덕션 샌드박스에 다시 적용할 수 있다. 외부 통신 정책은 게스트 밖에서 집행한다. 호스트 쪽 프록시가 페이로드를 복호화하지 않고 TLS 핸드셰이크의 호스트 이름을 확인하며, DNS도 걸러낸다. 계정 API 키는 별도 브로커가 보관해 작업 환경에 직접 전달되지 않고, 패키지 레지스트리 방화벽이 알려진 악성 npm·pip 패키지를 차단한다.

속도 면에서는 파일시스템을 원격 블록 스토리지에 두고 필요할 때 가져오는 방식을 택했다. 포크는 기록 시 복사(copy-on-write)로 처리하고, 미리 준비한 VM 풀과 최소 커널 덕분에 고객 볼륨 연결·마운트까지 포함해 샌드박스 하나를 넘겨받는 데 약 500ms가 걸린다고 한다. 회사는 "사용자 프로세스는 모니터링 에이전트의 권한을 물려받지 않는다"고 강조했다.

리플릿은 이번 재구축이 고객의 AWS·구글 클라우드·애저 환경에서 돌리는 '자체 클라우드 도입(BYOC)'의 기반이 된다고 설명했다. 수만 개 microVM을 쿠버네티스로 운영하는 방법은 후속 2부에서 다룰 예정이다. 제시된 수치는 모두 리플릿이 스스로 밝힌 내용이다.

## 핵심 포인트

- 리플릿이 샌드박스 엔진을 공유 커널 도커 방식에서 샌드박스별 커널을 둔 microVM 방식으로 재작성
- 수억 개 프로젝트를 데이터 손실·보고된 중단 없이 이전했다고 밝힘
- KVM과 클라우드 하이퍼바이저 기반, eBPF·LSM으로 감시·차단
- 리눅스 커널 CVE 6211건 중 96.1%를 회피했다고 자체 집계
- 샌드박스 할당에 약 500ms, 고객 클라우드에서 돌리는 BYOC 기반으로 활용

> 배경(편집자 설명): microVM은 일반 가상머신보다 가볍게 만든 VM으로, 컨테이너 수준의 빠른 시작과 VM 수준의 격리를 함께 노리는 기술이다.
