# 앤트로픽, 에이전트 기억 관리 연구 공개…'드리밍'으로 잘못된 기억 스스로 고친다

## 상세 요약

앤트로픽이 6일(현지시간) 공식 블로그에서 클로드의 장기 기억 관리 방식과 '드리밍(Dreaming)' 기술의 실험 결과를 공개했다. 드리밍은 AI가 일하지 않는 시간에 이전 세션 기록을 다시 살펴 기억의 오류를 고치거나 새 지식 구조를 만드는 기능이다. 지난 5월 처음 소개됐고, 이번에는 실제 작업 성능에 주는 영향을 수치로 내놨다. 핵심 결론은 기억을 많이 쌓기보다 중요한 정보를 골라 재구성하는 편이 낫다는 것이다.

포켓몬 레드 게임 실험에서 클로드 소네트 3.7은 약 1만 단계 동안 225개 폴더에 413개 파일을 만들며 거의 모든 정보를 저장했지만 배지는 1개만 얻었다. 클로드 페이블 5는 폴더 2개에 파일 9개와 요약 파일 1개만 두고 전략·이동 계획·직접 확인한 규칙 위주로 기억을 관리해 배지 4개를 얻었다. 다만 서로 다른 모델 간 비교여서 기억 방식만의 효과로 보기는 어렵다. 앤트로픽은 쓸모없는 기록이 늘수록 AI가 실제 작업보다 기억을 확인하고 정리하는 데 자원을 더 쓰게 된다고 설명했다.

드리밍의 오류 수정 효과도 확인됐다. 포켓몬센터 위치를 잘못 기억해 같은 길을 맴돌던 클로드는 드리밍이 과거 기록과 저장된 기억을 대조해 오류를 찾아낸 뒤 제 경로로 다음 도시에 도착했다. 잘못된 기억을 그대로 쓴 클로드는 목적지에 이르지 못했다.

대규모 문서 실험에서는 앤트로픽 내부 문서 약 35만 개 파일, 4억 2000만 토큰을 대상으로 클로드 오퍼스 5가 128차례 분석과 수정을 거쳐 위키 형태 지식 구조를 만들었다. 위키만 쓴 정답률은 13%에서 48%로, 검색과 위키를 함께 쓴 경우는 54%에서 61%로 올랐다(검색만 쓴 경우 53%). 검색과 위키를 결합하면 질문당 토큰이 약 2만 개 줄었고, 여러 문서를 종합해야 하는 기업 인수 관련 질문에서는 위키 정답률이 87%로 검색만 쓴 경우(73%)보다 높았다.

기억 관리 규칙 자체를 고친 사례도 있다. 인수 계약서 분석에서 여러 에이전트가 한 파일을 동시에 고치다 계약 내용 일부가 빠지자, 클로드가 원인을 분석해 계약별로 문서를 따로 쓰도록 규칙을 바꿨다. 그 결과 최종 법률 문서의 평가 기준 충족률이 72%에서 100%로 올랐다.

한계도 있었다. 일부 법률 문서 분석에서는 위키를 더해도 검색만 쓴 경우와 차이가 크지 않았고, 위키가 원본보다 커지는 사례도 나왔다. 기억을 검토·수정하는 데 추가 연산이 든다는 점도 과제다. AI타임스는 모델을 다시 학습시키지 않고도 경험의 저장·활용 방식만으로 장기 작업 성능을 높일 수 있음을 보여 준 연구라고 평가했다.

## 핵심 포인트

- 드리밍: 유휴 시간에 과거 세션을 검토해 기억 오류를 고치고 지식 구조를 재구성
- 포켓몬 실험에서 잘못 기억한 경로를 바로잡아 목적지 도달
- 35만 파일·4억 2000만 토큰 문서 실험에서 검색+위키 정답률 54%→61%, 질문당 약 2만 토큰 절감
- 계약별 문서 분리 규칙으로 법률 문서 기준 충족률 72%→100%
- 일부 작업은 효과 미미, 위키 비대화와 추가 연산 비용은 과제
