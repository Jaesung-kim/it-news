# 깃허브 액션 '워크플로 잠금 파일' 정식 지원…태그로 쓰고 커밋은 별도 파일에 고정, 공급망 공격 대응

## 상세 요약

깃허브 액션은 워크플로에서 쓰는 액션을 Git 저장소에서 내려받는다. Git 태그는 나중에 다른 커밋을 가리키도록 바꿀 수 있어서, 공격자가 멀쩡하던 태그를 악성 코드로 돌려놓는 공급망 공격이 가능하다. 그래서 그동안은 태그 대신 커밋 SHA 전체를 적어 고정하라는 권고가 일반적이었다. 글쓴이는 실제 사례로 tj-actions/changed-files 공격을 다룬 분석 글을 함께 소개했다.

깃허브는 10월 28일 체인지로그에서 '워크플로 잠금 파일(lockfile)'을 정식 출시(GA)했다고 밝혔다. 공개 프리뷰로 제공하던 기능을 엔터프라이즈 클라우드(데이터 레지던시 포함), 팀, 무료 요금제에서 정식으로 쓸 수 있게 한 것이다. 깃허브 CLI 확장 `gh actions-lock`을 실행하면 액션과 그 하위 의존성까지 담은 `.github/workflows/actions.lock` 파일이 만들어진다.

파이썬 코어 개발자 휴고 반 케메나데(Hugo van Kemenade)는 11일 블로그에서 이 기능을 실제 프로젝트에 적용하는 방법을 정리했다. 확장을 설치하고 `gh actions-lock`을 돌리면 SHA로 고정돼 있던 워크플로가 `actions/checkout@v7.0.1`처럼 읽기 쉬운 버전 태그 형식으로 바뀌고, 실제 커밋 정보는 잠금 파일에 기록된다. 수정된 워크플로와 잠금 파일은 함께 커밋해야 한다.

잠금 파일을 쓰도록 등록한 워크플로는 의존성이 모두 잠금 파일에 있어야 하며, 액션은 기록된 커밋으로만 실행된다. 워크플로 단위로 하나씩 적용할 수 있고, 엔터프라이즈·조직·저장소 관리자는 '잠금 파일 필수' 정책을 걸 수 있다. 디펜다봇이 액션 버전 업데이트를 올릴 때는 같은 PR에서 잠금 파일 항목도 다시 만든다. 리노베이트도 잠금 파일을 지원한다.

깃허브는 CI에서 잠금 파일이 최신이고 손상되지 않았는지 검증하라고 권한다. 글쓴이는 별도 작업에서 `gh actions-lock --verify`를 돌리는 예시를 보여 줬다. 깃허브 액션 보안 린터 zizmor는 1.32.0부터 잠금 파일을 지원하며, 이전 버전은 여전히 해시 고정을 요구한다. 글쓴이는 zizmor를 "강력히 권장한다"고 했고, Pillow와 CPython 등 저장소에 적용한 PR 4건을 예로 들었다.

다만 깃허브는 "잠금 파일은 예상치 못한 의존성 변경을 막아 주지만, 그 의존성이 안전한지까지 판단하지는 않는다"고 선을 그었다. 고정한 버전 자체에 문제가 있으면 잠금 파일로는 막을 수 없다는 뜻이다. 글쓴이도 업데이트를 바로 받지 않고 일정 기간 기다리는 '쿨다운' 설정을 함께 쓰라고 권했다.

## 핵심 포인트

- 깃허브가 10월 28일 액션 워크플로 잠금 파일을 무료 요금제를 포함해 정식 출시했다
- `gh actions-lock`이 액션과 하위 의존성의 커밋을 `actions.lock`에 기록하고, 워크플로는 버전 태그로 쓸 수 있다
- 관리자는 '잠금 파일 필수' 정책을 걸 수 있고, 디펜다봇·리노베이트가 잠금 파일까지 함께 갱신한다
- CI에서 `--verify`로 잠금 파일을 검증하라는 것이 깃허브 권고이며, zizmor는 1.32.0부터 지원한다
- 잠금 파일은 의존성 변경을 막을 뿐 의존성의 안전성을 보장하지는 않는다
