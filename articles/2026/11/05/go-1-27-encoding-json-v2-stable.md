# Go 1.27, 새 JSON 패키지 encoding/json/v2 정식화…약 6년 작업, 역직렬화 최대 10배 빨라져

- 분야: IT 뉴스
- 출처: The Go Blog, GeekNews
- 원문: https://go.dev/blog/jsonv2
- 발행일: 2026-11-04

## 상세 요약

Go 팀이 공식 블로그에서 `encoding/json/v2`와 `encoding/json/jsontext` 패키지가 Go 1.27에서 안정화돼 정식 제공된다고 밝혔다. 기존 `encoding/json`은 15년 넘게 쓰이면서 동작과 API의 한계가 드러났고, 새 패키지는 이를 해소하려는 약 6년 작업의 결과물이다.

작업은 2020년 말 다니엘 마르티가 가상의 v2 초안을 쓰면서 시작됐다. 조 차이는 `protojson`에 필요한 더 엄격한 JSON을 찾고 있었고, protobuf JSON 코드에서 프로토타입이 나왔다. 2023년 말 공개 논의와 2025년 초 정식 제안을 거쳐 Go 1.25에서 실험 기능으로 제공됐다.

글이 꼽은 v1의 문제는 뚜렷하다. 잘못된 UTF-8과 중복된 객체 이름을 허용하고, nil 슬라이스와 맵을 `null`로 직렬화하며, 구조체 필드를 대소문자 구분 없이 매칭한다. 포인터 리시버 `MarshalJSON` 호출이 일관되지 않고, 사용자 정의 `UnmarshalJSON` 안에서는 `Decoder.DisallowUnknownFields`가 효력을 잃는 API 한계도 있었다.

v2는 기본 동작을 엄격하게 바꿨다. 잘못된 UTF-8과 중복 이름은 오류가 되고, nil 슬라이스와 맵은 각각 `[]`와 `{}`로 직렬화된다. 필드 매칭은 대소문자를 구분하며, `omitempty`는 JSON 값이 비었는지(`null`, `""`, `[]`, `{}`)를 기준으로 판단한다. `time.Duration`은 기본 표현이 없어 옵션 없이 직렬화하면 오류가 난다. 동작 대부분은 옵션으로 조정할 수 있다.

성능은 방향별로 차이가 있다. 직렬화는 v1과 비슷한 수준이고, 역직렬화는 크게 빨라져 벤치마크에서 "improvements of up to 10x"를 보였다고 한다. v2가 v1보다 느린 경우에 대한 작업은 계속되며, Go 1.28에서 추가 개선이 예고됐다.

기존 코드를 당장 옮길 필요는 없다. v1 패키지는 무기한 지원되며, 공식 마이그레이션 가이드가 함께 제공된다. 기본값이 달라진 만큼 옮길 때는 옵션으로 v1 또는 v2 동작을 맞춰 가며 점검할 수 있다.

## 핵심 포인트

- `encoding/json/v2`와 `encoding/json/jsontext`가 Go 1.27에서 안정화
- 잘못된 UTF-8과 중복 이름 거부, nil 슬라이스·맵은 `[]`·`{}`로 직렬화, 대소문자 구분 매칭
- 역직렬화는 최대 10배 빨라졌고 직렬화는 v1과 비슷한 수준
- v1은 무기한 지원되며 마이그레이션은 선택 사항
- Go 1.28에서 추가 성능 개선 예정
