# 깃북, SSO 결함으로 침해 당해…"모든 고객 데이터 노출된 것으로 간주"

- 분야: IT 뉴스
- 출처: GitBook 공식 사후 보고, GeekNews, Hacker News
- 원문: https://www.gitbook.com/status/security-incident-2026-11-03
- 발행일: 2026-11-04

## 상세 요약

문서 플랫폼 깃북이 11월 2일 발생한 보안 침해의 사후 보고서를 공개했다. 최고경영자 사라 탄도프스키와 공동창업자 겸 최고기술책임자 사미 페세가 서명했다. 깃북은 공격이 고객사 한 곳을 겨냥했고 상당 부분 자동화와 AI로 진행됐다고 설명했다. 다만 보고서에는 AI 사용을 뒷받침하는 구체적인 증거가 제시되지 않았다.

공격의 출발점은 로그인 흐름의 결함이었다. 깃북은 "Using a flaw in GitBook's SSO login flow, they were able to create login sessions acting as GitBook staff"라고 밝혔다. 공격자는 직원으로 위장한 세션으로 내부 저장소에 들어갔고, 잘못 설정된 GitHub 앱의 인증 정보를 거쳐 클라우드플레어 API 키까지 확보했다. 이 키로 운영 환경의 비밀값과 인프라 전체 접근 권한을 얻었다.

사후 보고서의 시간표(UTC)를 보면 진행은 빨랐다. 11월 2일 12시 27분 표적 고객사의 계정이 처음 탈취됐고, 16시 32분 직원 세션과 소스 코드 접근, 17시 48분 운영 환경 접근으로 이어졌다. 18시 10분 내부 경보가 울렸고, 19시 58분 SSO 결함을 고쳤으며, 20시 32분 침해 계정을 막고 앱을 내렸다. 공격자의 접근 시간은 2일 저녁 약 2시간 45분, 3일 새벽 약 40분이었다.

공격자가 접근할 수 있었던 범위는 넓다. 깃북 API 토큰, 통합 토큰과 비밀값, 세션 서명 비밀값, 인증이 필요한 문서 사이트, 고객이 허용한 저장소에 대한 GitHub·GitLab 연결 권한, 문서와 스페이스 같은 고객 콘텐츠가 포함된다. 초기 공지는 사이트 방문자가 깃북 어시스턴트에 입력한 질문도 대상으로 꼽았다. 결제 정보, 비밀번호, IP 주소는 침해되지 않았고 콘텐츠 변조 증거도 없지만, 깃북은 모든 고객 데이터를 노출된 것으로 간주했다.

대응 과정에서 깃북은 내부와 고객용 비밀값을 모두 교체하고, 스테이징과 운영 노드를 재생성했으며, 기존 API 토큰을 무효화했다. 앱과 인증 문서 사이트는 3일 11시 56분까지 15시간 넘게 내려가 있었다. 회사는 "We chose a longer outage over that risk"라고 설명했다. 그동안 공개 문서는 캐시로 일부 시간 유지됐다.

고객은 새 API 토큰을 만들어 기존 앱에 반영하고, 연동한 외부 도구와 통합의 비밀값을 교체해야 한다. 자체 백엔드로 인증 접근을 쓰면 서명 키도 다시 만들어야 하고, MCP 서버 이용자는 다시 인증해야 한다. Git Sync 키는 깃북이 교체했으므로 별도 조치가 필요 없다는 것이 최신 안내이며, 필요하면 Git Sync와 GitLab을 다시 연결하면 된다. 환경 로그에서 점검할 IP로는 94.183.188.91, 45.139.84.195, 198.251.83.217을 제시했다. 깃북은 네트워크 강화와 탐지 투자를 약속했고, 몇 주 안에 추가 보고서를 내겠다고 밝혔다.

## 핵심 포인트

- SSO 로그인 결함으로 직원 세션을 만든 공격자가 약 5시간 만에 운영 환경에 도달
- API 토큰, 통합 비밀값, 고객 콘텐츠까지 접근 가능해 모든 고객 데이터를 노출로 간주
- 결제 정보, 비밀번호, IP 주소는 침해되지 않았고 콘텐츠 변조 증거도 없다고 밝힘
- 고객은 API 토큰과 연동 비밀값을 교체하고 공개된 IP 3개를 점검해야 함
